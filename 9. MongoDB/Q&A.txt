an)MongoDB typically handles relationships using either embedding (storing related data within the same document) or
referencing (linking documents across collections using references). Embedding is suitable for one-to-few relationships,

Q)What is the difference between MongoDB and a traditional SQL database?

fixed schema, which provides structure and consistency.

Q)What is an index in MongoDB?
an)An index in MongoDB is a special data structure that improves the speed of data retrieval operations on a collection. Indexes

Q)Why are indexes important in MongoDB?
an)Indexes are important because they significantly enhance the performance of queries. Without indexes, MongoDB must perform a
full collection scan, examining every document to find the ones that match the query criteria. This can be slow, especially for
large collections. Indexes allow MongoDB to quickly locate the data without scanning the entire collection.

Q)What is the benefit of using embedded documents in MongoDB?
an)Embedded documents allow you to store related data together in a single document, which can improve read performance by

Q)What is the difference between embedding documents and using references in MongoDB?
an)Embedding Documents: Stores related data together in the same document, which is efficient for read operations and keeps
related data localized.
Using References: Stores related data in separate documents and links them using references (ObjectIds). This is more flexible
and can handle large or frequently changing data more efficiently.

Q)What is the impact of storing large complex documents in MongoDB?

thoughtfully and consider breaking down very large documents into smaller, related ones if necessary.
